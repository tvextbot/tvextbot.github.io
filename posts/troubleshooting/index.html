자동매매 주문이 안 될 때 확인할 것 (문제 해결 가이드)

얼러트는 울렸는데 주문이 들어가지 않았다면, 원인은 대부분 트레이딩뷰 얼러트 → 웹훅 → TVExtBot → 거래소 중 한 곳에 있습니다.
이 글의 순서대로 하나씩 확인하면 대부분의 문제를 직접 찾을 수 있습니다.

가장 먼저: 텔레그램 알림을 확인하세요

TVExtBot은 주문 결과와 에러 정보를 텔레그램 알림봇으로 보내 드립니다. 에러 알림이 왔다면 그 내용이 원인을 가장 빠르게 알려 줍니다. 알림봇을 아직 설정하지 않았다면 먼저 설정해 주세요. → 텔레그램 개인 알림봇 사용법

※ 단, 주문메시지의 조건식이 맞지 않거나 주문 시간대 밖이어서 건너뛴 경우는 정상 동작이므로 텔레그램 알림이 오지 않습니다. 알림도 주문도 없다면 이 두 옵션을 먼저 확인해 주세요. → 주문메시지 추가 옵션

1. 얼러트가 실제로 울렸나요?

트레이딩뷰 오른쪽의 얼러트 → 로그 탭에서 해당 시각에 얼러트가 기록되었는지 확인합니다.

  • 로그에 없음 → 얼러트 조건이 맞지 않았거나 얼러트가 멈춰 있습니다.
    • 얼러트 목록에서 얼러트가 활성 상태인지(중지·만료되지 않았는지) 확인해 주세요.
    • 조건을 “봉 닫힐 때 한 번” 으로 했다면, 봉이 마감되어야 얼러트가 울립니다.
  • 로그에 있음 → 다음 단계로 넘어갑니다.

2. 웹훅 설정이 맞나요?

  • 트레이딩뷰에서 웹훅을 쓰려면 유료 요금제(Essential 이상)와 2단계 인증이 필요합니다.
  • 얼러트의 알림 탭에서 웹훅 URL이 체크되어 있어야 합니다.
  • 웹훅 URL은 인증키 버전에 따라 다릅니다. 반드시 본인의 메시지 작성화면에 있는 웹훅 URL을 복사해 넣어 주세요. 다른 버전의 URL을 쓰면 주문 에러가 발생합니다.
  • 인증키를 새로 구매·변경했다면 기존 얼러트의 웹훅 URL도 새 URL로 바꿔 주세요.

자세한 설정 화면은 웹훅URL에 의한 자동매매를 참고해 주세요.

3. 주문메시지가 올바른가요?

  • 주문메시지는 반드시 확장프로그램의 메시지 작성화면에서 만들어 그대로 복사해 주세요. 직접 고치다 따옴표나 괄호가 하나라도 틀리면 주문이 실행되지 않습니다.
  • 메시지는 TVM:{ 로 시작해서 }:MVT 로 끝나야 합니다.
  • 하나의 얼러트에 넣을 수 있는 주문메시지는 최대 10개입니다.
  • 전략(strategy) 얼러트라면 메시지 칸에 {{strategy.order.alert_message}} 가 있어야 하고, 얼러트 조건에서 전략 스크립트를 골라야 합니다. → 얼러트 메시지 정리
  • 스크립트·설정·주문메시지를 바꿨다면 얼러트를 다시 만들어야 합니다. 얼러트는 만든 시점의 내용으로 동작합니다. (단축 주문메시지는 주문 내용만 바꿀 때 얼러트를 다시 만들 필요가 없습니다 → 단축 주문메시지 사용법)
  • 단축 주문메시지를 쓰는 경우, 메시지 리스트에서 해당 주문메시지를 삭제하면 사용할 수 없습니다. 삭제 후 다시 등록했다면 주문ID가 바뀌므로 얼러트를 다시 설정해 주세요.
  • 주문메시지 리스트에서 해당 메시지가 비활성화되어 있으면 실행되지 않고 텔레그램으로 알려 드립니다.
  • 주문메시지의 account 가 API키 등록화면의 계정명과 같은지 확인해 주세요. 계정명을 바꾸면 기존 메시지로는 API키를 찾지 못합니다.
  • 각 항목의 의미는 주문메시지 항목 설명을 참고해 주세요.

4. 인증키와 거래소 API 연결 상태는?

확장프로그램의 API키 등록화면에서 확인합니다.

확인할 것해결 방법
거래소 버튼이 [연결중] 인가?[차단] 이면 주문이 중지된 상태입니다. 버튼을 눌러 [연결중]으로 바꿔 주세요.
거래소 버튼에 락이 걸려 있나?유료 거래소는 유료 인증키가 필요합니다. → 인증키 등록&구매가이드
무료(TRIAL) 인증키인가?무료 인증키는 테스트넷에서만, 한 달간 사용할 수 있습니다.
인증키 사용 기간이 남아 있나?기간이 끝나면 메일과 텔레그램으로 알려 드립니다. 인증키를 새로 구매해 등록해 주세요.
API키를 거래소에서 재발급·삭제했나?새 API키와 비밀키를 다시 입력해 주세요.

5. 거래소 API키 설정은?

  • API키에 거래(Trade) 권한이 있는지 확인합니다. 선물 거래라면 선물 권한도 필요합니다.
  • 거래소가 IP 등록(화이트리스트) 을 요구하는 경우, 본인의 API키 등록화면에 표시된 IP주소를 모두 등록해야 합니다. IP주소도 사용하시는 버전에 따라 다르니 꼭 본인 화면의 값을 사용해 주세요.
  • 무료 인증키로 테스트넷을 쓸 때는 IP 등록 없이 API키를 만들어 주세요.
  • 거래소별 발급 방법은 거래소 API 발급 방법을 참고해 주세요.

6. 분당 주문 횟수를 넘지 않았나요?

하나의 거래소에서 1분 동안 실행할 수 있는 주문 횟수는 인증키 종류에 따라 제한됩니다.

인증키분당 주문 횟수
TRIAL1회
STANDARD구매 시 선택한 10회 · 15회 · 20회

제한을 넘는 주문은 백업 서버로 한 번 더 시도한 뒤에도 초과 상태면 실행되지 않고 텔레그램으로 초과 에러를 알려 드립니다. 1분이 지나면 다시 정상적으로 매매됩니다. 여러 종목의 얼러트가 같은 시각(예: 정각 봉 마감)에 몰리면 제한에 걸리기 쉬우니, 종목 수와 주문 횟수를 함께 고려해 주세요.

7. 거래소 쪽 조건은?

주문이 거래소까지 전달되었어도 거래소가 거절하는 경우가 있습니다. 텔레그램 에러 알림에 거래소의 거절 사유가 표시됩니다.

  • 잔고 부족: 주문 수량(잔액 대비 %)에 비해 잔고가 부족하거나, 현물·선물 지갑 사이에 자산을 옮기지 않았습니다.
  • 최소 주문 금액·수량 미달: 잔액 대비 %가 너무 작으면 거래소의 최소 주문 단위보다 작아질 수 있습니다.
  • 청산할 포지션이 없음: 이미 청산된 상태에서 청산 주문이 오면 실행할 것이 없습니다.
  • 포지션 모드 차이: 바이낸스 선물의 양방향(헤지) 모드에서는 청산을 “청산(매수포지션종료)“과 “청산(매도포지션종료)“으로 나눠야 합니다. → 바이낸스선물 양방향 포지션 설정법
  • 지정가 주문 미체결: 지정가로 주문하면 가격이 닿지 않아 체결되지 않을 수 있습니다. 거래소의 미체결 주문 목록을 확인해 주세요.

8. 그래도 해결되지 않으면

  • 확장프로그램이 최신 버전인지 확인해 주세요. → 크롬확장프로그램 수동업데이트 방법
  • 트레이딩뷰 서버 점검이나 거래소 API 장애로 일시적으로 주문이 되지 않을 수 있습니다. 거래소 공지사항도 확인해 주세요.
  • 아래 내용을 함께 보내 주시면 빠르게 확인해 드릴 수 있습니다.
    • 얼러트가 울린 시각과 거래소·종목
    • 텔레그램으로 받은 에러 메시지 (캡처)
    • 사용한 주문메시지 (토큰 부분은 가려 주세요)
